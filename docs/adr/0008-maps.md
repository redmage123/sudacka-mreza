# ADR-0008: Maps — Leaflet.js + OpenStreetMap
## Status: Accepted
## Date: 2026-03-21
## Decider: Chris Novak (CTO)

---

## Context

The platform has two mapping requirements:

1. **Courts directory** — each court needs a map pin showing its physical address. Users should be able to see where a court is located and get directions.

2. **Jurisdiction Finder** — the most valuable broken feature on the current site. The original Flash-based tool allowed users to click on a map of Croatia and find out which court has jurisdiction over a given geographical area. It has been completely non-functional since Adobe Flash EOL in December 2020. This must be rebuilt.

The owner specified Leaflet.js + OpenStreetMap.

---

## Decision

**Leaflet.js 1.9** with **react-leaflet 4** React bindings.

Tile provider: **OpenStreetMap** (free, no API key, GDPR-compliant, community-maintained).

**Court pins:** Each `Courts` collection entry has `lat` and `lng` fields. The `CourtDetailPage` shows a Leaflet map with a single pin and popup (court name, address, phone). The `CourtsPage` shows all courts as clustered pins using `leaflet.markercluster`.

**Jurisdiction Finder:** A choropleth map of Croatia divided into judicial jurisdiction areas. Each polygon represents the territorial jurisdiction of a court. Clicking a polygon highlights it and shows the responsible court in a sidebar.

GeoJSON data source: **GADM (Global Administrative Areas)** dataset for Croatia, post-processed to assign each administrative unit to the correct court. If Dražen provides the original jurisdiction boundary data, that takes priority.

The `JurisdictionMap.tsx` component:
1. Loads Croatian jurisdiction GeoJSON from `web/public/data/croatia-jurisdictions.geojson` (built into the SPA)
2. Renders each polygon with Tailwind-token colours (primary navy fill, gold border on hover)
3. On polygon click: fetches the responsible court from `/api/courts?where[jurisdictionArea][equals]=polygon-id`
4. Displays court name, address, and link to court detail page in a side panel

---

## Alternatives Considered

**Google Maps API**
- Pros: Familiar to users; excellent Croatian geocoding; Street View
- Cons: Requires API key with billing enabled ($200/mo free tier then pay-per-use); GDPR complications (user IP sent to Google); data sovereignty concern; API key management overhead; rate limiting on public sites
- Rejected: Cost and GDPR concerns for a civic site

**Mapbox**
- Pros: Beautiful map styles; good documentation; generous free tier (50k loads/month)
- Cons: Requires API key; Mapbox GL JS is heavier than Leaflet (2MB vs 40KB); free tier limits are adequate for MVP but uncertain at scale; US company (data sovereignty)
- Rejected: Leaflet is sufficient for the requirements; no API key needed

**OpenLayers**
- Pros: More powerful than Leaflet for complex GIS operations; WMS/WFS support
- Cons: Significantly larger bundle size; steeper learning curve; overkill for map pins and polygon overlays
- Rejected: Complexity exceeds requirements

**ArcGIS JavaScript SDK**
- Appropriate for enterprise GIS systems
- Rejected: Enterprise licensing; wrong scale; Croatian judicial data doesn't need enterprise GIS features

---

## Consequences

**Positive:**
- Leaflet + OpenStreetMap: zero API costs, no rate limits, no billing surprises, no API key to manage or rotate
- GDPR-compliant: tile requests go to OpenStreetMap servers, which is standard open infrastructure; no user tracking
- Leaflet is 42KB minified+gzipped — excellent bundle size
- react-leaflet provides clean React bindings with SSR-compatible dynamic imports (important for `vite-plugin-ssg`)
- Fixes the #1 most-complained-about broken feature on the current site

**Negative:**
- Leaflet does not include a geocoder by default — if users want to search "Ilica 12, Zagreb" to find the responsible court, a separate geocoding service is needed. Mitigation: use OpenStreetMap's Nominatim geocoding API (free, rate-limited) via `leaflet-control-geocoder` plugin
- The jurisdiction GeoJSON data must be sourced and verified. Croatian court jurisdiction boundaries are not perfectly aligned with administrative boundaries. The GADM data is a good starting point but will need manual correction. This is a dependency on the client (Dražen) to verify polygon accuracy.

**Risk:**
- `react-leaflet` requires special handling for SSR/SSG because Leaflet uses `window` and `document` directly. In `vite-plugin-ssg`, the `JurisdictionMap` and `CourtMap` components MUST be dynamically imported with `{ ssr: false }` to prevent build errors. This is a known and well-documented pattern for Leaflet + SSG.
- The GeoJSON file for Croatian jurisdictions could be large (500KB+). It should be loaded lazily only when the JurisdictionFinder page is visited, not bundled with the main JS chunk.
